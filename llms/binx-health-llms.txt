# binx health

> binx health, inc. is a Boston, Massachusetts point-of-care diagnostics company. Its binx io
> platform is the first FDA-cleared, CLIA-waived molecular point-of-care test for chlamydia
> (Chlamydia trachomatis) and gonorrhea (Neisseria gonorrhoeae), pairing ultra-rapid PCR
> amplification with proprietary electrochemical detection to return central-lab-equivalent
> results in about thirty minutes from female vaginal swabs or male urine — so a patient can be
> tested, diagnosed and treated in a single visit. binx health publishes no public developer
> program, API reference, or machine-readable specification.

This file was generated by API Evangelist from a public probe of binx health's own surface. It is
a third-party profile, not a binx health document.

## Status of the API surface

- **No public API.** binx health does not operate a developer portal, publish an API reference,
  or ship a machine-readable contract (OpenAPI, AsyncAPI, GraphQL SDL, JSON Schema, or a Postman
  collection). `/api`, `/developers`, `/developer`, `/docs`, `/api-docs` and `/integrations` all
  return 404 on `mybinxhealth.com`, and no `api.*`, `developer.*` or `docs.*` host resolves.
- **No SDKs or client libraries.** Nothing first-party on npm, PyPI, Maven Central, NuGet,
  pkg.go.dev, RubyGems, Packagist or crates.io.
- **No `/.well-known/` discovery surface.** See `well-known/binx-health-well-known.yml` for the
  full probe record, including the paths checked and the control paths used.
- **No A2A agent card.** `/.well-known/agent-card.json` and the legacy `/.well-known/agent.json`
  both 404 on the primary host.

## Machine-readable endpoints that DO exist, and what they are not

Two endpoints on `mybinxhealth.com` return structured data. Neither is a binx health product API,
and API Evangelist does not score them as one:

- `https://mybinxhealth.com/wp-json/` — the WordPress REST API of the corporate marketing site.
  It exposes the CMS (posts, pages, media, plugin namespaces), not the binx io platform.
- `https://mybinxhealth.com/wp-json/mcp/mcp-adapter-default-server` — the default server created by
  the WordPress MCP adapter plugin. `tools/list` returns HTTP 401 (`rest_forbidden`), as does
  `/wp-json/wp-abilities/v1/abilities`. This is CMS plumbing shipped by a plugin, not an agent
  interface binx health authored or documents.

## Do not confuse these domains

- `binxhealth.com` is a **parked Squarespace "Coming Soon" page**. It returns HTTP 200 with an
  identical 3135-byte HTML body for *every* path, including `/openapi.json`, `/swagger.json` and
  `/.well-known/agent-card.json`. Those 200s are soft-404s and are not evidence of anything.
- `www.binxhealth.dev` no longer resolves to binx health; it presents a TLS certificate for an
  unrelated host.
- `imaware.health` / `onimaware.com` belong to **imaware**, a separate company that acquired binx
  health's at-home consumer testing business in December 2023. binx health retained the
  point-of-care molecular diagnostics business. imaware's API is not binx health's API.
- `github.com/binxhealth` now carries the display name "imaware everywhere" and links to
  `app.onimaware.com`; its repositories are Grails/JavaScript infrastructure plugins with no API
  specifications. Ownership after the divestiture is ambiguous, so it is not attributed here.
